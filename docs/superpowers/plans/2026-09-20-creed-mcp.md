# Creed MCP — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Exponer los datos de Creed (Whoop, entrenos, comida, medidas, documentos de la nutri) a claude.ai mediante un servidor MCP remoto autenticado con Supabase OAuth 2.1, con tools de lectura y escritura.

**Architecture:** El MCP vive en `apps/web/app/api/mcp/route.ts` (mcp-handler v2, stateless). Cada tool es una función pura `(ctx, input) => output` en `apps/web/lib/mcp/tools/*`, con `ctx = { supabase (cliente con el JWT del usuario → RLS), userId, now }`. Supabase Auth actúa como servidor OAuth; `apps/web` sirve la página de consentimiento y el metadata de recurso protegido. Whoop sigue sincronizándose a Postgres (webhook + cron), ahora con backfill completo y medidas corporales.

**Tech Stack:** Next 16 (App Router, Vercel), `mcp-handler@2`, `@modelcontextprotocol/server@2`, `zod@4`, `@supabase/supabase-js@2.105` + `@supabase/ssr`, Supabase (Postgres + Auth OAuth 2.1), vitest 4, pnpm workspaces + turbo.

**Spec:** `docs/superpowers/specs/2026-09-20-creed-mcp-design.md`

## Global Constraints

- Nombres de tools `snake_case`; **descripciones y errores en español**.
- Zona horaria del atleta: `Europe/Madrid`. Fechas de entrada `YYYY-MM-DD`; instantes `ISO 8601`.
- Todas las tools usan el cliente Supabase **del usuario** (RLS). Service role solo en el cron de Whoop.
- No se borra código legado. No se toca `apps/mobile`.
- Cobertura ≥ 80 % en `apps/web/lib/mcp/`.
- Commits convencionales con trailers `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>` y `Claude-Session: https://claude.ai/code/session_01SHMYeRZELYXqVMyZapvwS3`.
- Tests de integración contra Supabase **local** (`pnpm db:start`). Cada test crea su usuario con `auth.admin.createUser` y lo borra al final.
